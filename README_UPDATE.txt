DEAD ROOMS — апдейт v2: «потоки» (hold) + выбор вида каста в редакторе навыков + редактор карт с вкладкой «Мобы»
(архив накопительный: подходит и тем, у кого уже стоит первая версия — повторно применённое пропускается)

ЧТО ВНУТРИ
1) Новый режим навыка "hold": true — зажал и держишь в любой момент (на бегу, в прыжке), запас тратится,
   отпустил — восстанавливается с того места, где остановился. mana_cost у такого навыка = мана В СЕКУНДУ.
   Поля навыка: hold, duration (запас, сек), mana_cost (мана/сек), recharge (сек полного восстановления,
   по умолчанию = cooldown), recharge_delay (пауза перед восстановлением), interval (период эффекта, сек).
   Пример: у мага навык «Огненный поток» (fire_stream). Подробности — README.md, раздел про навыки.
2) Восстановлен map_editor.py (его удалили коммитом «редактор мобов», поэтому launch_map_editor.bat
   не открывал редактор) и в него подключена вкладка «Мобы».

3) В редакторе навыков (launch_map_editor.bat -> вкладка «Навыки») у каждого активного навыка список «Вид каста»:
   «Обычный» / «С зажатием (стоя на месте)» (channel) / «Поток (зажать: запас + мана в секунду)» (hold).
   Поля формы и их подписи подстраиваются под выбранный вид (запас, мана в секунду, восстановление, период эффекта).
   При смене вида лишние флаги и поля убираются из skills.json сами.

ЗАТРАГИВАЕТ
spells.py, main.py, hud.py, multiplayer.py, data/skills.json, data/characters.json, map_editor.py,
README.md, CLAUDE.md (документация — по возможности, не критично).

УСТАНОВКА
1. Распакуйте архив в папку проекта (рядом с main.py).
2. Дважды щёлкните apply_update.bat (или: python apply_update.py).
3. Скрипт вносит правки в ваши файлы по содержимому — ваши локальные изменения (например, black_hole)
   сохраняются. Перед правкой делается копия <файл>.bak_before_update. Повторный запуск безопасен.
   Если какой-то файл не подошёл, он НЕ изменяется, а скрипт пишет, что именно не нашлось.
4. В игре нажмите F5 или перезапустите. Редактор — launch_map_editor.bat.

ОТКАТ
Верните файлы из копий *.bak_before_update (или git checkout).

Проверено: на чистом клоне репозитория и на копии с локальными правками; повторный запуск; игровой цикл;
редактор под виртуальным дисплеем.
