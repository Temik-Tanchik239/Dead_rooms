# DEAD ROOMS — заметки для работы над кодом

2D-платформер в духе Dead Cells на **pygame-ce**. Карты — экраны, нарисованные вручную символами
в `data/maps/*.json`. Почти весь контент (физика, оружие, мобы, карты, навыки, герои, босс, свет)
вынесен в `data/*.json` и `assets/*.json` — **код трогать не нужно**, чтобы менять контент.
`F5` в игре перезагружает все данные и картинки на лету.

Подробная инструкция по контенту для пользователя — в `README.md` (большой, на русском).
Этот файл — техническая карта кода для меня.

## Запуск и сборка
- Из исходников: `uv run main.py` (зависимости в `pyproject.toml` / `uv.lock`, нужна pygame-ce).
- Редактор карт: `python map_editor.py` или `launch_map_editor.bat` (использует только `tkinter`).
- Сборка EXE: `build_exe.bat` (`uv sync` + `uv run pyinstaller DEAD_ROOMS.spec`) → `dist/DEAD_ROOMS.exe`.
  - `make_icon.py` собирает `.ico` из `assets/app/icon.png` для PyInstaller.
  - Рядом с EXE кладутся редактируемые `dist/data` и `dist/assets` — они **приоритетнее** встроенных
    (см. `core.FROZEN` / `BASE` / `RESOURCE_BASE`).

| `spells.py` | ~900 | Заклинания/активные навыки игрока. Реестр `@spell("тип")`: `dash`, `nova`, `heal`, `shield`, `projectile`, `chain_lightning`, `strike_area`, `beam` (мгновенный пронизывающий луч по линии до `range`, задевает всех, чей центр ближе `width` пикселей до линии), а также телекинез инженера `telekinesis` (притянуть дальних / оттолкнуть ближних врагов и предметы в области), `telekinesis_cone` (оттолкнуть всех в конусе перед собой), `telekinesis_hold` (оглушить и держать ближайшего к курсору; удерживаемый каст — см. ниже). Телекинез дотягивается до предметов через `pl.drops` (ставится в `Game.step`/`HostSession.step`); `_shove()` толкает моба без урона. `cast()` — проверка маны/кулдауна + вызов эффекта (в `a` добавляется `_sid` — id навыка); `active_skills()` + `pl.skill_index` — список и текущее заклинание для вертикальной книги мага в HUD (`spellbook()` — то же тройкой prev/cur/next), `ready()` — готовность для авто-каста. `icon_path(sid, a)` — поиск иконки (поле `icon` → `icons/skill_<id>.png` → `icons/<id>.png`). `cast_frames(sid, a)` — кадры анимации применения навыка (поле `cast_anim` → `skills/<id>/cast` → `skills/<id>/cast.png`), рисуются в `Player.draw`; нет кадров — процедурная вспышка. `projectile_spec(a)` — вид снаряда заклинания: тип + поля `projectile_*` (`PROJECTILE_FIELDS`, вкл. `projectile_pierce`) + автоподхват `assets/projectiles/<id навыка>.png` или папки кадров. Тип `"at_cursor": true` — снаряд появляется в точке курсора со скоростью 0 (касты «в область»: воронка/зоны/шторм/дождь — работу делает поведение пули в projectiles.py). **Удерживаемые заклинания (`"channel": true` в skills.json, как ульта Bane в Dota 2):** `cast()` лишь запускает каст (`begin_channel` → `pl.channel = {sid, t, max, ...}`), перезарядка стартует в `channel_stop()`, а не при нажатии; пока герой колдует, `Player.update` зовёт `channel_update()` — она проверяет прерывания (`_channel_break`: отпущена клавиша навыка `pl.skill_held`, A/D, S/↓, прыжок, перекат, атака, падение/лестница/захват) и лимит `duration`, затем хук `tick`. Урон прерывает каст из `Player.hit`. `@spell`-функция удерживаемого заклинания возвращает `False` (не вышло — мана и КД не тратятся) или словарь стартового состояния; хуки регистрируются `channel("тип", tick=..., end=...)` (`CHANNELS`). Старт требует стоять на земле без нажатых A/D/S (`_channel_blocker`). Пока идёт каст, `cast()`/`ready()` игнорируют новые нажатия, а `swap_skill` заблокирован. **Заклинания-«потоки» (`"hold": true`, третий режим):** клавишу держат в любой момент (бег/прыжок/удары/урон не прерывают); у навыка запас `duration` сек (`pl.hold_pool[sid]`, нет записи = полный), пока клавиша зажата — запас тратится, мана по `mana_cost` **в секунду**; отпустил — `hold_update` возвращает запас с того значения, на котором остановились, за `recharge` сек с нуля (по умолчанию = `cooldown`; пауза `recharge_delay`). `cast()` для `is_hold(a)` зовёт `hold_start` (кулдауна нет, нужен запас и мана ≥ `mana_cost × HOLD_MIN_START`), каждый кадр `Player.update` зовёт `hold_update` (отдых всех потоков + ведение активного `pl.hold`), `hold_stop(why)` — конец (release/empty/mana/target/grab/swap; при empty/mana/target и зажатой клавише ставится `pl.hold_latch` — заново только после отпускания). Эффект: хуки `channel(...)` типа, если есть (`tick`/`end` общие с channel), иначе `@spell`-функция повторяется каждые `interval` сек. Сеть: `hold_net(pl)` / `hold_net_apply(pl, hd, hr)` — хост шлёт `"hd": [sid, t]` и `"hr": {sid: запас}`, у клиента `pl.hold_view = True` и поток только «картинка» (`pl.hold["view"]`). Клоны героев (навык `clone`, `@spell("clone")`) — модуль `clone.py`. **Сила каста (только маг):** у каждого заклинания своё значение 0…1 (`pl.cast_power[sid]`, нет записи = 0; см. `spell_tablet.py` — ползунок на планшете); множители линейны: при 1.0 урон ×2 (`power_skill` — копирует навык и умножает только `damage`), мана ×2.5, перезарядка ×2, время каста ×2 (`POWER`, `power_scale(pw, key)`); применяются в `cast()`, `ready()`, `hold_cost`, `hold_blocker`, `hold_start` (сохраняет `pl.hold["pw"]`), `hold_update` и `channel_stop`. Вкл/выкл — `has_cast_power(cid)` по флагу `"cast_power"` героя в `characters.json`; у остальных героев сила всегда 0 (поведение прежнее). У героя с силой каста ЛКМ каст НЕ запускает (в `Player.update` и `Game.skill_held` ветка ЛКМ гейтится `not has_cast_power`) — заклинание применяет только клавиша навыка; у инженера (spellcaster без cast_power) ЛКМ осталась. В сеть уходит действием `"skpow:<sid>:<pw>"` (≤60 симв.), в сейв — поле `"cast_power"` в снапшоте героя (только значения > 0). |

## Как всё связано (центральные механизмы)

**`core.CFG` — единый словарь конфигов.** `reload_data()` читает все `data/*.json` в `CFG[имя]`,
плюс `boss` (из `assets/boss/boss.json`, моб кладётся в каталог как `__boss__`), `skill_tree`,
`skill_menu` (окно 4×2 = 8 ячеек; всё дерево листается колесом мыши — слотов может быть сколько угодно), карты (`map_defs`), персонажей. Босс-моб и размеры мировой сетки (`COLS`/`ROWS`)
вычисляются здесь же. F5 → `reload_data()` + `anim.clear_cache()`.

**Система персонажей (core.py).** У каждого героя свои правки `player`/`weapons`/`skills`/
`skill_tree`/`skill_menu`. `apply_character(cid)` применяет их в `CFG`; `use_char(cid)` —
контекст-менеджер для временного переключения (нужно в мультиплеере, где у игроков разные герои
одновременно — см. `_VIEWS` кэш). `char_def`/`char_look`/`char_player_cfg` достают данные героя.

**Реестры-декораторы — главный паттерн расширения.** Новый тип контента = функция/класс с
декоратором, параметры в JSON. Не надо менять диспетчер:
- `@movement("имя")` в `movement.py`
- `@attack("имя")` в `attacks.py`
- `@behavior("ключ")` / `@on_death("ключ")` в `projectiles.py`
- `@spell("тип")` в `spells.py` (активные навыки/заклинания игрока)
- `@hand_attack("имя")` в `boss_hands.py`
- пресеты света в `lighting.py`

**Невидимость (`invisibility.py`).** Один эффект для `Player` и `Mob`. Наложение: навык `type: "invisibility"` (`spells.py`), статус `{"invisible": ...}` в `status.apply` (любой `effect`), поле `invisible` у моба в `mobs.json` (читает `Mob.__init__`), код `invisibility.apply`. Тик — `Player.update` / `status.tick`. Мобы не замечают невидимого: `movement.look` сбрасывает `m.aggro`, если цель `w.pl` невидима; босс — `seen_players(w)` в `Mob.update` (агр сбрасывается, если видимых нет), цели рук — `Hand.targets`; вражеский `homing` пропускает невидимых; в мультиплеере хост выбирает `w.pl` через `invisibility.pick_target`. Зоны ударов и контакт по-прежнему бьют всех (`players_of`). Сброс при атаке: `Player.start_attack` (после проверки маны), `spells.cast`/`hold_start` (по `invisibility.breaks(a)`: всё, кроме `dash/heal/shield/invisibility`, либо `breaks_invisibility` в навыке), `Mob.start_attack`, атаки рук босса. Рисование: `Player.draw`/`Mob.draw`/`Dummy.draw` заворачивают тело в `invisibility.ghost(...)`. Сеть: снимок игрока `"iv"`, строка моба — последний элемент; клиент принимает в `apply_stats`/`apply_mobs` (`net_apply`, свой предсказываемый герой короткое время доверяет локальному состоянию).

**Фазы атак** везде одинаковы: `windup` (замах) → `active` (удар) → `recovery` (отдых), плюс
`cooldown`. Касается `attacks.Attack`, оружия игрока, `boss_hands.HandAttack`.

**Сетка мира.** У каждой карты `"pos": [x,y]`. Выходы `L/R/U/D` ведут к соседней клетке; `maps.world_links`/
`target_of`/`resolve` считают переходы. `check()` валидирует (две карты в клетке, выход в пустоту,
нет парного выхода) — ошибки красным в игре и в консоли.

**Главный цикл — `Game` (main.py).** Состояния через флаги: `menu_mode` (`start`/`pause`/`None`),
`level_menu` (выбор навыка при лвл-апе), `show_world` (карта мира, пауза), `net` (None=одиночка,
иначе Host/Client сессия). Ключевые методы: `new_game`, `go`/`take_exit` (переходы между картами),
`place`, `clear` (зачистка + спавн босса на последней карте круга), `gain_xp`/`choose_level_skill`, `pickup`.

**Механизмы (`mechs.py`).** Данные — `data/mechs.json`; расстановка — список `"mechanisms"` в JSON карты. Проксодетектируемое API (паттерн как у ящиков): `create` → `block` → каждый кадр `presolve` + `update` → `state`/`apply_state` в мультиплеере. Канал — имя связи: кнопка/рычаг (иначе `CONTROLS`) выдают в `room.mech_signals`, остальные слушают (`listen`). Перенос: `update` двигает платформы и `carry` сажает на них героя и мобов (ноги в полосе над платформой, прыжок отпускает). Порталы — пара через `pair`, работают только друг с другом.

**Мирные NPC и торговля (`npc.py`, `trade.py`).** NPC живут в `room.npcs` (НЕ в `room.mobs`) — по образцу ящиков: недоступны для ударов/снарядов игрока и невидимы для ИИ мобов (ящики/манекены/клоны уже так исключены; NPC — тем более, его просто нет в списках целей). E у торговца открывает окно торговли (в сетевой игре запрещено): купить у торговца, продать своё; окна — см. `trade.py`. Ассортимент конкретного торговца — `data/npcs.json -> assortment` (пусто = все предметы игры), правится на вкладке «Торговцы» редактора; расстановка — вкладка «NPC» редактора карт или поле `"npcs"` в JSON карты.

**Мультиплеер.** Хост считает ВСЁ (мир, мобов, пули, всех игроков). Клиенты шлют только ввод,
получают снимки и интерполируют чужих (свой герой считается локально для отзывчивости).
`content_sig()` сверяет, что у всех одинаковые `data/`. Порты: TCP 5555 (игра), UDP 5556 (поиск). Ввод игрока — `NetKeys` из 6 бит `[влево, вправо, вверх, вниз, пробел, клавиша навыка зажата]`; удерживаемый каст целиком считает хост, в снимке он едет как `"ch": [sid, t, max]`, а у клиента `Player.channel` — только картинка (`"view": True`) для HUD/анимации. Поток (`"hold": true`) так же считает хост; в снимке игрока `"hd": [sid, t]` (активный поток) и `"hr": {sid: запас}` (у неполных).

## Данные (`data/`)
`player.json` (физика, мана, регенерация, полоски) · `weapons.json` (combo, projectile, slot, mana) ·
`mobs.json` (hp, move, attacks, anims, xp, light; `cc_immune` — иммунитет к заморозке/оглушению; `invisible` — моб невидим: `true`/секунды/`{time, transparency, break_on_attack}`; механики: `guard.cooldown` — щит спереди, `regen.delay/rate` — регенерация, `on_death.explode.damage/radius/knockback` — взрыв при смерти, `on_death.split.mob/count/hp_k` — разделение на мелких) ·
`invisibility.json` (процент прозрачности для всех/игрока/мобов, `fade`, `warn`, `break_on_attack`) ·
`projectiles.json` (у типа пули можно задать `effect`, напр. `{"freeze":2.0}` — накладывается при попадании) ·
`mechs.json` (типы механизмов: рычаг `lever`, кнопка `button`, дверь `door`, лифт `elevator`, телепорт `teleporter`, платформа `mover`; размер w/h в клетках, цвет, скорость, подсказка, reach — см. `mechs.py`) ·
JSON карты может нести поле `"wires": [{"a": id, "b": id}]` — провода между механизмами (соединения для удобства редактора: в игре не видны и не читаются, пишет/читает только `mech_panel.py`) ·
JSON карты может нести поле `"mobs": [{"mob": id, "x": клетка, "y": клетка}]` — расстановка мобов вкладкой «Мобы» редактора (`mob_panel.py`; игра спавнит их в `GameMap.spawn` наряду с мобами из легенды) ·
`skills.json` (98 навыков; активные: dash/nova/heal/shield/clone (клоны героев)/invisibility (мантия невидимости) + заклинания мага chain_lightning/strike_area/projectile/beam
+ телекинез инженера telekinesis/telekinesis_cone/telekinesis_hold; пассивки max_hp/max_mana/damage/move_speed/mana_regen/mana_cost_reduction/note_radius/note_power;
50 тематических навыков героев — по 10 на героя: рыцарь (молот/меч-бумеранг/щит/свет/мины/знамя), бард (волны/аккорды/стихи/метроном), инженер (ракеты/гатлинг/лазер/дроны/магнит/масло), маг (копьё/звездопад/гроза/колодец/кристаллы), тень (залпы/воронка/дождь/клинки/ловушки); см. `_add_hero_skills.py`;
`mana_cost` (у `hold` — мана в секунду), `cooldown`, `effect`, `color`, `icon`; режимы использования: обычный / `"channel": true` (стоя) / `"hold": true` (поток с запасом: `duration`, `recharge`, `recharge_delay`, `interval`; пример — `fire_stream` у мага и `metronome` у барда); у активного навыка можно задать анимацию каста:
`cast_anim` — папка/файл кадров, `cast_size` [ш,в], `cast_offset` [dx,dy], `cast_animation` — длительность, сек) ·
`characters.json` (5 героев: stats/weapons/skills/tree/overrides; `spellcaster: true` — чистый заклинатель:
нет оружия/подбора, ЛКМ или Q кастует текущее заклинание, C/V листают книгу из трёх; у мага и инженера это включено, ПКМ у них свободна под оружие из инвентаря (`allowed_weapons: null`), `weapons: []` — стартового оружия нет; `bard: {...}` — бард (гитара и ноты, см. `bard.py`; id `bard` заменил `wanderer`, старый `last_character` откатывается на героя по умолчанию); `crossbows: {...}` — арбалетчик (Тень): два мини-арбалета вместо оружия, виды снарядов — навыки `category: "ammo"` в `skills.json`, см. `crossbow.py`) ·
`maps.json` (order, общая legend — включая `O` = чекпоинт, настройки, lighting, world) · `maps/<id>.json` (rows, pos, legend,
mob_pool, фон, свет, `morgart_layout`, `containers`, `decor`, `mechanisms`, `npcs` — список NPC `[{"type": id, "x", "y"}]`).
`npcs.json` (`sell_ratio` — доля цены при продаже; `npcs` — типы NPC: `trader` (Торговец Барт), `villager` (Житель), `guard` (Стражник);

пустой = торгует всеми предметами игры; правится вкладкой «Торговцы» редактора).
**Текущая кампания — мир Энеллы** (сгенерирован `make_envella_world.py`, 25 карт `env_<x>_<y>`
в `data/maps/`; `start = env_7_0` — таверна, `order` — BFS от таверны, босс Моргарт `env_9_-2` в конце).
Старые учебные карты (`start/platforms/spikes/hill/blocks/my_map/kanalisaciya/secret`) убраны в

выходы, они были с ошибками `maps.check()`).
`settings.json` (fullscreen, mouse_aim, menu_layout,
last_character, player_name). `maps/_*.json` — заготовки, не читаются.

## Управление (для тестов)
A/D бег · Space/W прыжок · S+Space спрыгнуть · ЛКМ оружие1 / ПКМ оружие2 (зажать — комбо) ·
K/Shift перекат (неуязвим) · E подобрать (также E у торговца — окно торговли) · Q навык (удерживаемые `channel`, напр. захват инженера, работают, пока Q зажата и герой стоит на месте; «потоки» `hold` — пока Q зажата, хоть на бегу, пока есть запас), C/V смена навыка · E подобрать · R рестарт ·
M карта мира · **F5 перезагрузка данных** · **F6 меню разработчика** · F4 сетка клеток · F3 хитбоксы / редактор кнопок меню ·
F11 полный экран. Персонаж целится в курсор (`mouse_aim` в settings.json).
