# multiagent — «несколько агентов» для pi

Оркестратор параллельных pi-агентов. Главный агент (вы) может раздать подзадачи,
запустить `node multiagent/run.mjs` и собрать готовые результаты из `multiagent/out/`.

## Зачем

Внутри одного сеанса pi — один агент с одним контекстом. Этот раннер добавляет
настоящую параллельность: **каждый подзаголовок — отдельный pi-агент** (SDK,
`createAgentSession`) со своей моделью, своим контекстом и своими инструментами.

## Требования

- Node.js ≥ 20 (проверено на 22).
- Пакет pi SDK уже стоит там же, где pi: `~/.pi/agent/install/releases/<версия>/node_modules/@earendil-works/pi-coding-agent`
  (скрипт резолвит его из окружения pi; если запускать из другого места — поставьте пакет в проект:
  `npm i @earendil-works/pi-coding-agent`).

## Как пользоваться

```bash
# 1) подготовить подзадачи — папка с файлами *.task.md:
mkdir -p multiagent/tasks
echo "Разбери main.py, найди места для хуков крафта и выпиши их." > multiagent/tasks/analyze_main.task.md

# 2) запустить (сухой прогон — модель не вызывается):
node multiagent/run.mjs --dir multiagent/tasks --dry-run

# 3) настоящий запуск, до 4 агентов одновременно:
node multiagent/run.mjs --dir multiagent/tasks --cwd "C:/Users/artem/Desktop/DEAD_ROOMS" --parallel 4
```

### Формат подзадачи

`*.task.md` — чистый текст промпта. Желательно: цель, файлы, точный желаемый результат,
ограничения. Агент сам читает/правит файлы в `cwd` и пишет объяснение в `out/<имя>.md`.
Он обязан ответить строкой `RESULT_OK` / `RESULT_FAIL`.

### Флаги

| Флаг | Назначение |
|------|-----------|
| `--dir` | папка с `*.task.md` |
| `--manifest <файл>` | JSON `{"tasks":[{id,prompt},...]}` |
| `--prompt` + `--id` | разовая задача из строки |
| `--parallel N` | максимум одновременных агентов (по умолчанию 4) |
| `--cwd <путь>` | рабочий каталог агентов (по умолчанию — текущий) |
| `--out <путь>` | куда писать результаты (по умолчанию `multiagent/out`) |
| `--dry-run` | не вызывать модель, только проверить раскладку |

## Предостережения

- Каждый агент = **реальный вызов LLM** (той же модели и квоты, что у pi). Промпты делайте узкими:
  одна задача — один агент; иначе это дорого и медленно.
- Не давайте параллельным агентам **править одни и те же файлы** — будут конфликты.
  Разделяйте по файлам/модулям или делайте агентов «аналитиками» (результат в md, правки вносит главный агент).
- Квиты: при ограниченной квоте лучше 2–3 агента параллельно, чем 6.
