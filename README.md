# DEAD ROOMS
## Запуск на Windows

**Самый простой способ:** соберите EXE один раз:
1. Установите Python 3.10+ и [uv](https://docs.astral.sh/uv/).
2. Дважды щёлкните `build_exe.bat` в папке проекта.
3. После успешной сборки запускайте `dist/DEAD_ROOMS.exe` двойным щелчком. Для игры больше не нужны Python и uv.

Сборка создаёт `dist/DEAD_ROOMS.exe` и копирует рядом редактируемые папки `dist/assets` и `dist/data`. Эти внешние папки имеют приоритет над встроенными ресурсами, поэтому картинки можно заменять **после сборки**, не пересобирая EXE. Для запущенной игры сначала закройте её, замените файл, затем запустите снова.

### Автоматические фоны редактора карт

Поместите изображения в `assets/backgrounds/` — редактор автоматически добавит их в список «Фон».
Поддерживаются PNG, GIF, JPG/JPEG, BMP, TIFF и WebP. Кнопка «Обновить фоны» перечитывает папку
без перезапуска редактора. Имена пунктов списка формируются из имени файла: например,
`dark_forest.png` станет `Dark Forest`. Пути к выбранным изображениям сохраняются в JSON
карты относительно `assets/`. Загрузчик Pygame, уже входящий в зависимости игры, используется для форматов, которые Tk не читает напрямую.

### Изменение размера и расположения кнопок меню
1. Запустите игру и откройте главное меню (или нажмите `Esc` во время забега).
2. Нажмите `F3` — включится редактор кнопок меню.
3. Перетаскивайте кнопки мышью, чтобы менять их положение.
4. Наведите курсор на кнопку и прокрутите колёсико мыши или используйте `+` / `-`, чтобы изменить размер.
5. Нажмите `F3` или `Esc`, чтобы выйти из редактора. Настройки сохраняются автоматически в `data/settings.json` в разделе `menu_layout`.

Редактор позволяет отдельно настраивать размеры и позиции кнопок «Продолжить», «Новая игра» и «Выход». В собранной версии EXE настройки сохраняются в `dist/data/settings.json`.

### Оформление меню через PNG
Если запускаете EXE, меняйте файлы именно в `dist/assets/menu/`. При запуске из исходников меняйте `assets/menu/`:
- `background.png` — фон главного меню;
- `button.png` — обычная кнопка;
- `button_selected.png` — подсвеченная кнопка;
- `cursor.png` — курсор мыши в меню (PNG с прозрачностью; точка клика — левый верхний угол картинки).

Фон затемняется лишь слегка. Курсор по умолчанию ограничивается размером 64×64 пикселя; лучше подготовить PNG около 32×32.

**Запуск из исходников:** `uv run main.py` (зависимости подтянутся сами, используется pygame-ce). Раскладка клавиатуры — английская.

Управление: A/D — бег, Space/W — прыжок (отпустил — прыжок ниже), S+Space — спрыгнуть с платформы,
W/S у лестницы — лазать, **ЛКМ — оружие 1, ПКМ — оружие 2** (зажми кнопку — комбо идёт само; J/L работают как запасные),
K/Shift — перекат (отменяет удар, неуязвим), E — подобрать оружие, F5 — перезагрузить data/*.json и картинки, **F6 — меню разработчика** (см. ниже), F4 — сетка с номерами клеток, **M — карта мира** (сетка карт с координатами), R — заново.
Персонаж при ударе поворачивается к курсору, стрелы/склянки/заклинания летят в курсор (`"mouse_aim": false` в data/settings.json — вернуть удары строго вперёд).

## Мультиплеер по локальной сети (до 4 игроков)
Все компьютеры должны быть в одной сети (один Wi-Fi или один роутер) и с **одинаковой версией игры** (одинаковые папки `data/`).

1. Главное меню → **МУЛЬТИПЛЕЕР**. Сверху можно ввести своё имя.
2. **СТАТЬ ХОСТОМ** — открывается лобби (как экран выбора героя). Сверху написан ваш IP, например `192.168.1.5:5555`.
   Справа — список игроков, на карточках — метки, кто какого героя выбрал. **НАЧАТЬ ЗАБЕГ** (или Enter) — старт для всех.
3. **ПОДКЛЮЧИТЬСЯ** — поле для IP хоста (`192.168.1.5` или `192.168.1.5:5555`, Ctrl+V вставляет). Ниже сами собой
   появляются найденные в сети игры — достаточно нажать на строку. Затем выберите героя в лобби и ждите старта от хоста.

Как работают механики вместе:
- Хост считает весь мир, остальные присылают ему своё управление — у всех одна и та же игра.
- Отряд переходит между картами вместе: кто первым вошёл в выход, тот переводит всех. Двери запираются, когда все отошли от входа.
- Мобы нападают на ближайшего игрока; удары по площади и вражеские снаряды задевают всех.
- Опыт за убийство получает каждый; уровни, навыки, мана и оружие у каждого свои. E — подобрать оружие рядом с собой.
- 0 HP — игрок падает. Постойте рядом с ним 3 секунды, чтобы поднять (35% HP); зачистка карты поднимает всех павших.
  Погибли все — хост нажимает **R**, начинается новый забег. Пройдены все карты — хост нажимает **Enter** (следующий круг).
- **Esc** открывает меню, но игра не останавливается (персонаж в это время стоит). В меню паузы кнопка **ПОКИНУТЬ ИГРУ**.
- Подключиться можно и во время забега — новый игрок появится рядом с союзниками.
- В сетевой игре не работает F5 (перезагрузка данных) и F6 (меню разработчика), а меню уровня заменено плашкой вверху экрана, чтобы не останавливать игру.

Плавность у подключившихся: свой герой считается прямо на компьютере игрока (отзывается на кнопки сразу),
а мобы и союзники показываются с небольшой задержкой и плавно между снимками от хоста. Задержка подбирается сама:
по кабелю ~25 мс, на Wi-Fi с энергосбережением (пакеты приходят пачками) ~100 мс. Для лучшего результата — кабель
или отключить энергосбережение Wi-Fi-адаптера у игрока.

Если не подключается:
- Windows при первом запуске хоста спросит про брандмауэр — разрешите доступ для **частных сетей**.
  Порты: **TCP 5555** — игра, **UDP 5556** — поиск игр в сети. Если поиск не находит хоста, введите IP вручную.
- IP хоста можно узнать в лобби или командой `ipconfig` (строка «IPv4-адрес»).
- «Разные файлы игры» — у хоста и у вас отличаются карты, мобы, оружие или герои в `data/`: скопируйте одну и ту же сборку всем.

Код сети — `multiplayer.py` (протокол, лобби, расчёт мира на хосте, отрисовка у клиента).

## Освещение (блоки света)
Блоки света рисуются на карте как любые другие символы (сквозь них можно ходить):
- `*` — факел (тёплый, живое мерцание, искры), `o` — фонарь (ровный тёплый свет, слегка качается),
  `+` — кристалл (голубой, «дышит»), `%` — магическая сфера (фиолетовая, пульсирует).
- **Цвет и сила.** В редакторе карт внизу слева — панель **«Свой свет»**: вид (факел, фонарь, кристалл, сфера, невидимый свет),
  цвет (10 готовых: тёплый, белый, красный, оранжевый, жёлтый, зелёный, голубой, синий, фиолетовый, розовый — или любой через «Свой цвет…»)
  и **сила 1–5** (1 — слабый огонёк, 3 — обычный, 5 — очень яркий: больше радиус, ярче, сам светильник крупнее).
  Нажмите «Рисовать этим светом» и ставьте ЛКМ. Для каждого сочетания редактор сам выберет свободную букву и запишет её в легенду карты.
- Готовые символы `* o + %` тоже есть в палитре («Свет: …»), там же поле **«Темнота карты, %»**.
- Вручную в легенде карты: `"Й": {"light": {"preset": "torch", "color": "красный", "strength": 4}}`
  (цвет — название, `[255, 80, 40]` или `"#ff8040"`).

Как работает: карта с блоками света затемняется, а вокруг источников — мягкие цветные пятна света с плавным мерцанием,
сиянием вокруг огня. Свой небольшой свет есть у каждого игрока, светятся снаряды и мобы-огоньки (`light` у моба в `data/mobs.json`).
Перекрывающиеся источники складываются мягко и не засвечивают картинку в белое. Цветной свет окрашивает всё вокруг.
Карты без блоков света выглядят как раньше. Для примера на первой карте («Вход») стоят несколько светильников, в том числе зелёный кристалл силой 4.

Настройка:
- у карты в `data/maps/<id>.json`: `"darkness": 0.7` (0 — светло, 1 — тьма), `"ambient": [14, 14, 30]` — оттенок темноты;
- свои источники: в легенде карты `"Q": {"light": {"color": [255, 80, 60], "radius": 200, "flicker": "torch", "draw": "orb"}}`;
- заготовки света (`lights`) и общие настройки (`lighting`: свет вокруг игрока, свечение снарядов, качество `resolution`) — в `data/maps.json`.
Все поля описаны в начале `lighting.py`. В сетевой игре освещение у всех одинаковое.

## Как добавлять контент (код трогать не надо)
- data/player.json — вся физика: гравитация, ускорение, койот-тайм, прыжок, перекат, лестницы.
  - `hp_regen_delay` — сколько секунд игрок должен не получать урон до начала лечения (по умолчанию 5.0).
  - `hp_regen` — скорость лечения в HP/секунду (по умолчанию 5.0). Поставьте `0`, чтобы отключить регенерацию.
- data/weapons.json — оружие. `slot`: 1 или 2. `combo` — список ударов (windup → active → recovery, damage, reach [w,h],
  knockback, lunge). Есть `projectile` — тогда это стрелок/метатель: имя пули из projectiles.json (`"arrow"`),
  или `{"type": "arrow", "speed": 800}` (пуля + правки), или полное описание на месте; `count` + `spread` — веер.
- data/projectiles.json — типы пуль, общие для оружия и мобов (см. раздел «Пули»).
- data/mobs.json — мобы (см. раздел «Мобы»).
- data/maps.json + data/maps/*.json — карты, нарисованные вручную, и их порядок (см. раздел «Карты»).

## Карты (data/maps.json, data/maps/*.json)
Ничего не случайно: каждая карта нарисована символами, порядок прописан списком.

**Порядок** — `data/maps.json`:
```json
"start": "start",
"order": ["start", "platforms", "spikes", "hill", "blocks"]
```
Выход `next` ведёт на следующую карту в `order`, `prev` — на предыдущую. Выход `next` с последней карты — конец
прохождения («Enter: ещё круг», мобы на каждом круге сильнее на `loop_scale`). Карта может не входить в `order`
(как `secret` — тайник): туда ведут только выходы, в которых указан её id.

## Сетка мира (координаты карт)
У каждой карты в её файле `data/maps/<id>.json` есть поле **`"pos": [x, y]`** — клетка карты в общей сетке мира. `x` растёт вправо,
`y` — вниз, числа целые, могут быть отрицательными; в одной клетке — одна карта. Сейчас:

```
        x=0        x=1          x=2       x=3
y=-1                                      [blocks]
y= 0    [start]    [platforms]  [spikes]  [hill]
y= 1               [secret]
```
По сетке работают переходы: выход `right` (символ `R`) на карте с `"pos": [1, 0]` ведёт на карту с `"pos": [2, 0]`, `left` (`L`) — на `[0, 0]`,
`up` (`U`) — на `[1, -1]`, `down` (`D`) — на `[1, 1]`. Выход можно привязать и к конкретной клетке: `"1": {"exit": [3, 1]}`.
- **Переставить карты или переключить переходы** — поменять `pos`: например `"pos": [4, 0]` у `blocks` и его `D` перестанет вести на `hill`.
- **Игрок появляется** в выходе, ведущем обратно: ушёл вправо по `R` — появится у `L` соседней карты. Поэтому у соседей нужны парные выходы.
  `U` и `D` — лестницы на верхнем и нижнем краю (как раньше `^` и `v`).
- **Смешивать можно**: `<` / `>` (порядок `order`), id карты, `back`, `[x, y]` и `L R U D` работают вместе.
- **M в игре** — карта мира: клетки с именем, id и `[x, y]`, линии переходов (серая — в обе стороны, оранжевая — в одну), красная клетка — не зачищена,
  зелёная — зачищена, белая рамка — вы здесь; игра на паузе. В `data/maps.json`: `"world": {"reveal": "all"}` (`"visited"` — показывать только посещённые и их соседей),
  `"print_world": true` — печатать сетку в консоль при запуске и F5. Координаты текущей карты написаны в углу рядом с её именем.
- **Проверка**: две карты в одной клетке, `pos` не `[x, y]`, выход в пустую клетку, нет парного выхода обратно — красным слева сверху при запуске и по F5.

**Новая карта**: скопируй `data/maps/_template.json` в `data/maps/<id>.json`, нарисуй сетку, впиши `<id>` в `order` (или только дай ей `pos` и нарисуй выходы `L R U D`), нажми F5.

**Сетка** — `"rows"`: 50 строк по 50 символов (клетка 32 px). Экран показывает кусок карты 30x16 клеток, камера следует за игроком. Края рисуются тоже вручную: где стена —
там `#`, где проём — там выход. Нет стены на краю и нет выхода — это пропасть: упал — урон `fall_damage` и назад к
месту появления. F4 в игре показывает сетку с номерами столбцов и строк и символ под курсором.

**Легенда** — что значит символ. Общая — в `data/maps.json` → `legend`, у карты может быть своя `legend`
(добавляет символы или переопределяет общие только на этой карте). Общие символы:

| Символ | Что это |
|---|---|
| `.` | пусто |
| `#` | стена |
| `=` | платформа (запрыгнуть снизу, S+Space — спрыгнуть) |
| `H` | лестница |
| `x` | шипы (`damage` 10) |
| `<` / `>` | выход на предыдущую / следующую карту (по `order`) |
| `L` `R` `U` `D` | выход по сетке мира: влево / вправо / вверх / вниз (`U` и `D` — лестницы) |
| `P` | старт игрока (если пришёл не через выход) |
| `?` | случайное оружие на полу |
| `S` | случайный моб (из `mob_pool` карты или из всех) |
| `r c w g l b h` | конкретный моб: rotling, bone_caster, wisp, grave_brute, leaper, bat, hexer |

Запись легенды — строка-тип (`"wall"`) или словарь с полями:
- `type` — физика: `empty`, `wall`, `platform`, `ladder`, `spikes` (по умолчанию `empty`);
- `exit` — клетка-выход: `next`, `prev` (по `order`), `back` (туда, откуда пришёл), id карты, `left` / `right` / `up` / `down` (соседняя карта по сетке мира) или `[x, y]` (карта в этой клетке сетки); `arrive` — символ на целевой карте, у которого появиться;
- `player: true` — старт игрока; `mob` — id моба или `random`; `item` — id оружия или `random`;
- `sprite` — картинка клетки (путь в assets), `draw` [w, h] — размер (низ картинки по низу клетки, можно больше клетки — для декора),
  `offset` [x, y], `flip`; `color` [r, g, b] — цвет стандартной отрисовки; `damage` — урон шипов.

Примеры своей легенды карты:
```json
"legend": {
 "^": {"type": "ladder", "exit": "next"},
 "1": {"exit": "secret"},
 "G": {"type": "wall", "color": [150, 115, 40]},
 "t": {"type": "empty", "sprite": "decor/torch.png", "draw": [32, 64]},
 "a": {"exit": "boss", "arrive": "B"}
}
```

**Выходы.** Выход — группа соседних одинаковых символов с `exit` (например две клетки `>` в проёме стены). Игрок
появляется в выходе, который ведёт обратно туда, откуда он пришёл (или у символа `arrive`, или у `P`). Выход срабатывает,
когда игрок отошёл от места появления и снова зашёл в него. Вертикальные переходы — выход типа `ladder` на верхнем или нижнем
краю (на «Холме» `^` наверху лестницы, на «Глыбах» `v` внизу): игрок появляется сразу на лестнице.
Пока на карте живы мобы, все выходы закрыты красными блоками (`"lock": false` у карты — не закрывать).

**Фон** — у карты `"background": "backgrounds/crypt.png"` (любая картинка в assets), `"bg_mode"`:
`cover` — заполнить экран с сохранением пропорций (по умолчанию), `stretch` — растянуть, `fit` — вписать целиком,
`center` — как есть по центру, `tile` — замостить маленькой картинкой. `bg_dim` 0–1 — затемнить фон, чтобы стены читались лучше,
`bg_color` — цвет под фоном. Фон растягивается на всю карту (1600x1600), экран показывает его часть 960x512.

**Остальные поля карты**: `name` (видно в углу), `tiles` — свои картинки для всех клеток типа (`{"wall": "tiles/stone.png"}`),
`mob_pool` — кого спавнит `S` (`["bat", "wisp"]` или с весами `{"bat": 3, "wisp": 1}`), `difficulty` — множитель силы мобов,
`reward` — оружие после зачистки (`{"item": "random", "chance": 0.5}`), `lock`, `fall_damage`, `fill` — чем дополнить короткие строки.
Значения по умолчанию для `bg_*`, `tiles`, `lock`, `fall_damage` — в `data/maps.json`.

Ошибки в картах (не та длина строки, неизвестный символ, выход на несуществующую карту, нет картинки фона) пишутся
красным в левом верхнем углу при запуске и по F5, и в консоль.

## Мобы (data/mobs.json)
Базовое: name, hp, w, h (хитбокс), speed, contact (урон касанием), weight (шанс появления), mass (насколько тяжело
отбросить), flies (летает), armor (удары не сбивают), stun (сколько стоит оглушённым), sight / sight_y (обзор),
attack_gap (пауза между атаками), skin (картинка), draw [w, h], anims, anim_fps, blink (мигать на замахе), color,
invisible (моб появляется невидимым — см. раздел «Невидимость»).

**Движение** — `"move": {"type": ..., параметры}` (код: movement.py):
- `chase` — жёсткий агр: увидел игрока — прёт прямо на него и больше не отстаёт. Летуны летят по прямой.
  `jump` — запрыгивать на стенку в 1 блок, `drop` — спрыгивать с края, если игрок ниже, `patrol` — бродить до агра.
- `keep_distance` — держит дистанцию: `distance`, `band` (допуск), летуны — `height` (минус = выше игрока).
  Подходит/отходит, в пропасть не шагает.
- `loop` — летает по циклу, на игрока не реагирует: `shape` = circle | eight | line | path, `radius` [rx, ry],
  `period` (сек на круг), `points` [[dx, dy], ...] для path, `anchor: "player"` — кружить вокруг игрока, `reverse`.
- `stand` — стоит на месте.

**Атаки** — `"attacks": [ {...}, {...} ]` (код: attacks.py). Моб берёт первую готовую атаку, до которой хватает расстояния.
Общее: windup, active, recovery, cooldown, damage, knockback, range / min_range / range_y, mobile (двигаться во время
атаки), interrupt (false — замах не сбить), id + next (комбо: после атаки сразу следующая), anims (свои анимации фаз).
- `melee` — удар перед собой: `reach` [w, h], `lunge` (рывок).
- `circle` — удар по кругу: `radius`, `center` = self (вокруг себя) | player (туда, где стоял игрок). Зона видна на замахе.
- `shoot` — стрельба: `projectile`, `count` + `spread`, `burst` + `burst_gap` (очередь), `aim` = player | forward | ring | angle,
  `angle`, `offset` [x, y].
- `leap` — прыжок к игроку с ударом при приземлении. Прыгает на землю рядом с игроком (со своей стороны), а не на него:
  `land_offset`, `air_time` (выше/ниже дуга), `radius` (удар при приземлении), `track`. Место приземления видно на замахе.
  У летунов — рывок по прямой.

Новый паттерн движения — функция с `@movement("имя")` в movement.py; новая атака — класс с `@attack("имя")` в attacks.py.

## Пули (data/projectiles.json)
speed, vy, gravity, life, size, color, knockback, damage (если урон не задан атакой), aoe (взрыв), pierce (пробивает N
целей), bounces + bounce_damp (отскоки), sprite или frames + fps (картинка/серия PNG носом вправо), draw [w, h], rotate.
Поведения: `homing` (самонаведение: число или {rate, delay, range}), `accel` (+ max_speed / min_speed), `wave` {amp, freq},
`split` {into, count, spread | ring, damage} — распад на другие пули.
Новое поведение — функция с `@behavior("ключ")` (каждый кадр) или `@on_death("ключ")` в projectiles.py: оно включится у
любой пули, в описании которой есть этот ключ.

**Иконка игры** лежит в ассетах: `assets/app/icon.png` (квадратный PNG с прозрачностью, лучше 256×256). Сейчас там заглушка, замените её своей.

- Окно игры и значок на панели задач берут `icon.png` при каждом запуске: заменили файл в `assets` рядом с EXE, перезапустили игру, и пересобирать ничего не нужно.
- Иконка самого файла `DEAD_ROOMS.exe` (проводник, ярлык на рабочем столе) вшивается в EXE при сборке. После замены файла запустите `build_exe.bat` заново: `make_icon.py` соберёт из PNG многоразмерный `.ico` и передаст его PyInstaller. Если проводник показывает старую иконку, это кэш Windows.
- Есть готовый `.ico`? Положите его как `assets/app/icon.ico`, он будет использован для EXE вместо сборки из PNG. Нет файла иконки совсем — EXE получит стандартную.
Папку `data` держи рядом с `DeadRooms.exe`: JSON-файлы по-прежнему можно править без пересборки.
Для раздачи друзьям упакуй в архив всю папку `dist\DeadRooms`.

## Текстуры мобов и полный экран
- Текстура моба — PNG с прозрачным фоном в `assets/mobs/`. Рисуй персонажа **лицом вправо** (влево игра отразит сама), размер любой (лучше 2–4× от экранного).
- Новый моб: добавь запись в `data/mobs.json` и положи `assets/mobs/<id>.png` (или укажи свой путь в поле `"skin"`). Без файла моб рисуется цветным прямоугольником.
- **Анимации ходьбы и атак для каждого моба** — серии PNG на отдельные состояния; настройки задаются отдельно в записи каждого моба в `data/mobs.json`.
  Кадры клади в `assets/mobs/<id>/<состояние>/` (например `assets/mobs/rotling/walk/1.png`, `2.png` …; сортировка по номеру).
  Для ходьбы принимаются оба названия папки/настройки: `move` и `walk`.
  Состояния: `idle`, `move`/`walk`, `jump`, `windup` (замах), `attack` (сам удар; у атаки `leap` используется `jump`), `recovery`, `hurt`, `death`.
  Нет анимации — берётся запасная (move → idle, jump → move, …), затем обычный скин.
  Пример общей настройки конкретного моба:
  ```json
  "anims": {
    "walk": {"frames": "mobs/rotling/walk", "fps": 12},
    "idle": {"frames": "mobs/rotling/idle", "fps": 6},
    "hurt": "mobs/rotling/hurt"
  }
  ```
  `frames` — папка, шаблон (`mobs/rotling/walk_*.png`) или один PNG; `fps` — кадров в секунду; `loop: false` отключает зацикливание. Можно не указывать `frames`, если используешь папки по умолчанию `assets/mobs/<id>/<состояние>/`.
  Без `fps` кадры замаха/удара/отдыха подгоняются под длительность фазы атаки.
  **Своя анимация для конкретной атаки** — у нужного элемента в `attacks` добавь `anims`; это позволяет разным атакам одного моба иметь разные кадры:
  ```json
  "attacks": [{
    "type": "melee",
    "windup": 0.35,
    "active": 0.12,
    "recovery": 0.4,
    "anims": {"windup": "slash_windup", "attack": "slash", "recovery": "slash_recovery"}
  }]
  ```
  Тогда кадры положи в `assets/mobs/<id>/slash_windup/`, `assets/mobs/<id>/slash/` и `assets/mobs/<id>/slash_recovery/`. Если у атаки нет своего имени для фазы, используется стандартная анимация моба (`windup`, `attack`, `recovery`).
- `"draw": [w, h]` — размер картинки на экране; `w`/`h` — размер хитбокса (может быть меньше картинки). Земные мобы выравниваются по низу хитбокса, летающие — по центру.
- F5 перезагружает JSON и текстуры, F3 показывает хитбоксы (удобно подгонять `draw`), F11 — полный экран/окно.
- `data/settings.json`: `{"fullscreen": true}` — запуск в полный экран по умолчанию (Esc — выход).

## Скины игрока и снарядов
- **Игрок** — `assets/player/`: `idle.png` (скин по умолчанию), `jump.png`, `roll.png`, `attack.png` (меч), `shoot.png` (лук и метание), `hurt.png`, `ladder.png`
  и кадры бега в папке `move/` (1.png, 2.png, …). Всё рисуется лицом вправо. Пути и размеры — в `data/player.json`:
  `skin`, `anims` (состояние → файл или папка), `draw` [w, h] и `draws` (свой размер для roll / attack / shoot, там картинка шире), `anim_fps`.
  Положил кадры в `assets/player/<состояние>/` — анимация подхватится сама (как у мобов).
- **Снаряды** — `assets/projectiles/<имя типа>.png`, нос вправо. В `data/projectiles.json` у типа поля `skin` (путь), `draw` [w, h],
  `rotate: false` (не поворачивать по полёту, как у бомбы), `frames` + `fps` (серия PNG). Нет `skin` — ищется `assets/projectiles/<имя типа>.png`,
  нет файла — рисуется цветной круг. Новый тип снаряда = запись в JSON + PNG.
- F5 перезагружает и JSON, и картинки.

## Скины оружия
- `assets/weapons/<id>.png` — картинка оружия **носом вправо**, рукоять слева. Одна картинка = оружие в руке, на полу (подбираемый предмет) и в иконке HUD.
- **Иконки внизу слева** (панель прозрачная, рисуется поверх игры) — три квадрата 48x48: персонаж, оружие 1 (ЛКМ), оружие 2 (ПКМ). Картинки лежат в `assets/icons/`: `player.png` и `<id оружия>.png`
  (квадратные PNG, у существующих 64x64 с тёмной плиткой и рамкой). Другой файл — поле `icon` в `data/player.json` и в записи оружия в `data/weapons.json`.
  Нового оружия без иконки это не ломает: вместо неё рисуется сам скин. В углах иконки оружия — кнопка мыши и цена маны; если маны не хватает, иконка темнеет.
- Поля в `data/weapons.json`: `skin` (путь), `draw` [w, h] — размер на экране, `grip` [x, y] — точка хвата (px от левого верхнего угла при размере `draw`),
  `rest_angle` — угол в покое (градусы, + вверх), `rotate: false` + `fixed_angle` — не поворачивать (склянка), `style`: `slash` (дуга) или `thrust` (укол).
- В шаге комбо: `style` и `swing` [от, до] (градусы) — как идёт взмах, у удара есть белый след. Хитбокс по-прежнему задают `reach`/`knockback`; F3 показывает его.
- Новое оружие: запись в `weapons.json` + PNG. Руки персонажа берутся из `hand` / `hands` в `data/player.json` (кисть в px от центра ног, лицом вправо).

## Невидимость
Эффект, общий для героя и мобов (включая босса). Код — `invisibility.py`, общие настройки — `data/invisibility.json`.

**Что делает.**
- Юнит становится прозрачным: герой вместе с оружием, моб вместе с полоской здоровья. Прозрачность плавно набирается и спадает за `fade` секунд, а в последние `warn` секунд юнит мигает — «скоро проявится».
- Мобы **не замечают** невидимого игрока и не агрятся на него, а уже агрившиеся — теряют цель и возвращаются к патрулю/покою. Это касается и босса Моргарта: ни голова, ни руки не начинают атак против невидимого игрока. В мультиплеере моб выбирает ближайшего **видимого** игрока.
- **Атака из невидимости сбрасывает эффект:** удар оружием; у заклинателей — боевое заклинание; у моба — любая его атака (у босса — атака головы или руки). Рывок, лечение, щит и сама мантия невидимость не снимают. Для любого навыка это можно переопределить полем `"breaks_invisibility": true/false` в `skills.json`. Если удар не состоялся (нет маны/оружия) — эффект остаётся.
- Физика не меняется: уже запущенная атака моба с зоной поражения заденет игрока, если он в неё попал, а касание моба с `contact` по-прежнему наносит урон.

**Процент прозрачности** — `data/invisibility.json` (F5 в игре перечитывает файл):
- `transparency` — общий процент: `0` — юнит виден как обычно, `100` — не виден совсем (по умолчанию 70);
- `player_transparency` / `mob_transparency` — свой процент для героя и для мобов (строку можно убрать — тогда берётся общий);
- `fade` — секунд на плавное проявление/исчезновение; `warn` — за сколько секунд до конца начинать мигать (`0` — не мигать);
- `break_on_attack` — снимать ли невидимость при атаке (по умолчанию для всех эффектов).

Свой процент можно задать и в самом эффекте — он важнее общего: поле `transparency` у навыка или у моба.

**Способы наложить эффект** (везде можно задать `time`/`duration` — секунды, `0` или пусто — бессрочно; `transparency`; `break_on_attack`):
1. **Навык «Мантия невидимости»** — `invisibility_cloak` в `data/skills.json`, тип `invisibility`: `"duration": 10` (секунды), `"mana_cost": 25`, `"cooldown": 20`, необязательно `"transparency"` и `"break_on_attack"`. Сейчас он выдан герою **Тень** (`base_skills` в `data/characters.json`); чтобы дать другому герою — добавьте `"invisibility_cloak"` в его `base_skills` (с самого начала) или в `skill_tree` (откроется на уровне). В редакторе навыков (вкладка «Навыки») тип «invisibility» с полями «Длительность» и «Прозрачность, %».
2. **Моб, невидимый с рождения** — поле `invisible` в `data/mobs.json`: `true` (бессрочно), число (секунды) или объект `{"time": 8, "transparency": 90, "break_on_attack": false}`. С `break_on_attack: true` (по умолчанию) моб-засада проявляется при первой же атаке. В редакторе мобов — группа «Невидимость» на вкладке «Основное».
3. **Статус-эффект** — ключ `invisible` в любом `effect` (навык `nova`/`strike_area`, пуля из `projectiles.json`): `"effect": {"invisible": 6}` или `{"invisible": {"time": 6, "transparency": 90}}`. Накладывается так же, как заморозка/горение.
4. **Из кода:** `invisibility.apply(юнит, {"time": 10, "transparency": 80}, fx)`, снять — `invisibility.clear(юнит, fx)`.
Повторное наложение продлевает время (берётся большее) и обновляет прозрачность.

**Проверка в игре.** В меню разработчика (F6) есть кнопки «Невидимость: я» и «Невидимость: манекен» — включают/выключают бессрочную невидимость; у манекена над табличкой видно «Невидим».

## Мана
Каждое оружие тратит ману. Полоска — под полоской HP, при нехватке маны удар не начинается и полоска мигает рамкой.
- **У оружия** (`data/weapons.json`): `mana` — цена одного удара/выстрела, `mana_hit` — сколько маны возвращает попадание ближним ударом.
  Эти же поля можно написать **у конкретного шага комбо** (например финальный удар дороже) — шаг важнее оружия.
  У нового оружия без `mana` цена берётся из `data/player.json` → `mana.default_cost` (сейчас 5), так что бесплатного оружия не бывает, пока сам не поставишь 0. Цена первого удара видна в HUD рядом с названием.
- **Общие настройки** (`data/player.json` → `mana`): `max`, `start`, `regen` (в секунду), `regen_delay` (пауза восстановления после траты, сек), `default_cost`.
- **Вид полоски** (`mana.bar`): `x`, `y` (от нижнего края окна, минус — вверх; по умолчанию полоски стоят под иконкой персонажа), `w`, `h`, `color`, `back`, `border`,
  `flash` (цвет рамки при нехватке), `ticks` (деление через каждые N маны, 0 — убрать), `text` (числа), `fill_skin` / `back_skin` / `frame_skin` — картинки
  из `assets/` (по умолчанию `assets/ui/mana_fill.png` и `mana_frame.png`; уберёшь поле — будут цветные прямоугольники). Полоска HP настраивается так же: `hp_bar`.
- Логика маны — в `main.py` (`Player.start_attack`, `refresh_mana`, регенерация в `Player.update`), цена удара — `weapon.mana_cost`, рисунок полоски — `hud.py`. F5 применяет правки сразу.


### Активные навыки
- `Q` — использовать выбранный навык (у каждого своя перезарядка).
- `C` / `V` — переключить навык вперёд / назад.
- Активный навык отображается отдельной иконкой рядом с иконкой героя; затемнение и цифра показывают перезарядку.
- Новые навыки добавляются в `data/skills.json`. Готовые типы (`type`): `dash`, `nova`, `heal`, `shield`, `projectile` (выстрел снарядом в курсор), `chain_lightning` (молния с перескоком на соседей), `strike_area` (удар сверху по области, можно `stun`/`effect`), а также телекинез инженера: `telekinesis` (в области у курсора дальних врагов и предметы притягивает к себе, ближних — отталкивает; поля `range`, `radius`, `force`, `grip` — порог притягивания/отталкивания, `damage`), `telekinesis_cone` (отталкивает всех врагов в конусе перед собой; поля `range`, `angle` — половина угла конуса в градусах, `knockback`, `damage`), `telekinesis_hold` (останавливает и держит в стане ближайшего к курсору врага; поля `range`, `duration` — максимум времени удержания; с `"channel": true` это удерживаемое заклинание, см. ниже). `invisibility` («Мантия невидимости»: накладывает на применившего эффект невидимости на `duration` секунд, см. раздел «Невидимость»). Чтобы сделать совсем новый эффект — добавьте функцию с декоратором `@spell("тип")` в `spells.py`.
- **Удерживаемые заклинания (`"channel": true`).** Работают как ульта Bane в Dota 2: нажми клавишу навыка и **держи** её — герой стоит на месте и колдует, пока клавиша зажата, но не дольше `duration` секунд. На иконке навыка в HUD виден индикатор: иконка затемняется по часовой стрелке по мере расхода времени, в центре — оставшиеся секунды. Каст **прерывается**, и навык уходит в перезарядку (`cooldown` стартует именно в этот момент), если герой: отпустил клавишу, пошёл (A/D), пригнулся (S/↓), прыгнул, перекатился, атаковал или получил урон; также каст заканчивается, когда истёк лимит времени, цель погибла или вырвалась дальше `break_range` (по умолчанию `range × 1.5`). Начать каст можно только стоя на земле и не нажимая A/D/S; если цели нет или она невосприимчива к контролю (`cc_immune`), мана и перезарядка не тратятся. Сейчас так работает «Телекинетический захват» инженера; включить режим другому навыку можно полем `"channel": true` (нужен `@spell` с хуками `channel(...)` в `spells.py`). Без `channel` захват работает как раньше — разовый стан на `duration` секунд.
- **Меню разработчика (F6) и тренировочный манекен.** Только в одиночной игре; пока меню открыто, игра на паузе (клики по нему не превращаются в атаки). Строки «Опыт», «Здоровье», «Мана»: впиши число в поле и нажми «Выдать» (или Enter; Tab — следующее поле). Для здоровья и маны число может быть отрицательным — отнимает, но здоровье не опускается ниже 1; кнопки «Полное»/«Полная» восстанавливают до максимума, «До след. уровня» выдаёт ровно столько опыта, сколько не хватает. Если выданный опыт повысил уровень, меню закрывается и показывается обычное окно выбора навыка. Кнопки внизу: «Спавн манекена» (ставит его на землю рядом с героем, можно несколько), «Убрать манекены», «Сбросить счётчик» (обнуляет счётчики и снимает эффекты). Манекен стоит на месте, не умирает и не атакует; над ним видны последний удар, суммарный урон, DPS за 5 с и активные эффекты. Урон от оружия, пуль, заклинаний и горения считается; стан, заморозка и горение на него действуют, а вот ударами его не отбросить (толчки/притягивание заклинаниями двигают). Манекен не мешает «зачистке» комнаты и не держит двери закрытыми. Код — `devtools.py`.
- **Внешность манекена (ассеты).** Без файлов рисуется соломенное чучело, но его можно заменить своей картинкой — папка `assets/dummy/` (как `assets/boss/` у босса). Всё необязательно: **`dummy.png`** — одиночный скин (рисуется, пока нет анимации нужного состояния); **папки кадров** `idle/`, `hurt/` (только что ударили), `stun/` (оглушён), `frozen/` (заморожен), `burn/` (горит) с файлами `1.png, 2.png, …` — анимации состояний; если для состояния нет кадров, берётся следующее по цепочке `frozen → stun → idle → dummy.png → чучело по умолчанию`; **`dummy.json`** — настройки: `w`, `h` — хитбокс (применяется к новым манекенам), `draw: [ширина, высота]` и `offset: [dx, dy]` — размер и сдвиг картинки относительно хитбокса (по умолчанию размер хитбокса, низ картинки по низу хитбокса), `skin` — путь к скину внутри `assets` (по умолчанию `dummy/dummy.png`), `hurt_time` — сколько секунд играть анимацию удара, а также `anims` и `anim_fps` — как у обычных мобов (`fps`, `loop`, свои папки кадров). Заморозка и горение подкрашивают силуэт картинки, оглушение добавляет звёздочки над головой. **F5** перечитывает файлы и обновляет уже стоящих манекенов (хитбокс — только у новых). Поля `hp`, `xp`, `move`, `attacks` в `dummy.json` игнорируются — манекен всегда остаётся неубиваемым и неподвижным. В `assets/dummy/_template.png` лежит шаблон — нынешнее чучело в 4-кратном размере: нарисуйте поверх и сохраните как `dummy.png`.
- **Заклинания-«потоки» (`"hold": true`) — третий режим.** Зажми клавишу навыка и держи: эффект работает, пока держишь. В отличие от `channel`, **двигаться, прыгать, перекатываться, атаковать можно в любой момент** — поток прерывают только отпущенная клавиша, смена навыка (C/V), хват босса и кончившийся запас/мана; урон поток не сбивает. У навыка есть **запас** в секундах: пока клавиша зажата, он тратится, отпустил — **восстанавливается с того значения, на котором остановился** (не с нуля, как кулдаун), и пока в запасе что-то есть, навык можно включить снова в любой момент. Если запас или мана кончились при зажатой клавише, поток выключается и включится снова только после того, как клавишу отпустят. На иконке навыка — сектор запаса и оставшиеся секунды, а цена маны подписана как `14/с`. Поля навыка:
  - `hold` — `true` включает режим (если указан и `channel`, работает `channel`);
  - `duration` — полный запас, секунды (по умолчанию 3);
  - `mana_cost` — **мана в секунду** каста, пока клавиша зажата (по умолчанию 10); для старта нужна мана хотя бы на 0.1 с;
  - `recharge` — за сколько секунд запас восстанавливается с нуля до полного (по умолчанию равно `cooldown`); `cooldown` у потока иначе не используется;
  - `recharge_delay` — пауза в секундах перед началом восстановления после отпускания (по умолчанию 0);
  - `interval` — период повторения эффекта, секунды (по умолчанию 0.35). Работает для типов без собственных хуков: `projectile` (поток снарядов), `chain_lightning`, `strike_area`, `nova`, `telekinesis`, `telekinesis_cone` — эффект просто срабатывает заново каждые `interval` секунд, мана при этом списывается только по `mana_cost` в секунду. Для `telekinesis_hold` (у него есть хуки) вместо `interval` действует удержание цели: `"hold": true` вместо `"channel": true` даёт тот же захват, но без требования стоять на месте.
  Пример — «Огненный поток» мага (`fire_stream` в `data/skills.json`): `"hold": true, "duration": 3.0, "recharge": 6.0, "interval": 0.2, "mana_cost": 14`. Чтобы превратить любой другой навык в поток, добавь ему `"hold": true` и эти поля. Свой тип потока с особым поведением — `@spell("тип")` + `channel("тип", tick=..., end=...)` в `spells.py` (хуки общие с `channel`).
  - **Вид каста в редакторе.** В `map_editor.py` (вкладка «Навыки», `launch_map_editor.bat`) у каждого активного навыка есть список **«Вид каста»**: «Обычный» (без флагов), «С зажатием (стоя на месте)» (`"channel": true`) и «Поток (зажать: запас + мана в секунду)» (`"hold": true`). Набор полей и их подписи подстраиваются под выбранный вид: у «с зажатием» появляется «Макс. удержание, с» (`duration`), у «потока» — «Запас, с» (`duration`), «Мана в секунду» (`mana_cost`), «Восстановление, с» (`recharge`), «Пауза восстановл., с» (`recharge_delay`) и «Период эффекта, с» (`interval`; его нет у типов со своим ведением эффекта, например `telekinesis_hold`). При смене вида лишние флаги и поля убираются из `skills.json` сами.

- **Своя анимация применения навыка.** Во время каста поверх героя проигрывается анимация. Игра ищет кадры по порядку: поле `cast_anim` навыка в `data/skills.json` → папка `assets/skills/<id навыка>/cast/` с кадрами `1.png, 2.png, …` → файл `assets/skills/<id навыка>/cast.png`. Кадры рисуются носом вправо (игра отражает сама) и прокручиваются ровно за время каста. Размер и смещение задаются полями `cast_size` [ширина, высота], `cast_offset` [dx, dy] (dx — вперёд по направлению героя), длительность — `cast_animation` (секунды). Нет кадров — рисуется процедурная вспышка цвета навыка. Чтобы сменить анимацию — просто положи свои PNG в ту же папку и нажми F5.
- **Чародей (маг)** — чистый заклинатель: оружия и подбора нет, вместо иконок оружия показана книга из трёх заклинаний (предыдущее · текущее · следующее). `ЛКМ` или `Q` — применить текущее заклинание в курсор, `C`/`V` — листать книгу. Любому герою можно включить такой режим полем `"spellcaster": true` в `data/characters.json`.
- Заклинания могут накладывать статусы на врагов: заморозку (синий оттенок, стоит на месте), оглушение, горение (урон со временем) и невидимость (`{"invisible": 10}`). Это задаётся полем `effect` у навыка или у типа пули, либо полем `stun` у удара по области.
- **Иконка заклинания** (HUD, окно мага, экран навыков). Игра ищет по порядку: поле `icon` навыка в `data/skills.json` → `assets/icons/skill_<id>.png` → `assets/icons/<id>.png`. Просто положи файл, например `skill_fireball.png`, `skill_ice_shard.png`, `skill_arcane_orb.png`, `skill_frost_nova.png`, `skill_thunderstrike.png`, `skill_chain_lightning.png`, `skill_meteor.png`, и нажми F5. Нет файла — рисуется цветной кружок цвета заклинания. Своё имя файла — поле `"icon": "icons/мой_файл.png"`.
- **Снаряд заклинания** (тип `projectile`). Тип пули берётся из `"projectile"` (`fire_bolt`, `ice_bolt`, `arcane_bolt` — см. `data/projectiles.json`). Поменять картинку можно тремя способами:
  1. Положить `assets/projectiles/<id заклинания>.png` (например `fireball.png`) — подхватится сам. Для анимации — папка `assets/projectiles/<id заклинания>/` с кадрами `1.png, 2.png, …`.
  2. Указать в навыке поля `projectile_skin` (путь к PNG) или `projectile_frames` (папка/шаблон кадров) + `projectile_fps`, `projectile_draw` [w, h] (размер на экране), `projectile_rotate` (false — не поворачивать), а также `projectile_size`, `projectile_color`, `projectile_speed`.

  `"fireball": {"projectile": "fire_bolt", "projectile_skin": "projectiles/my_fire.png", "projectile_draw": [40, 24], ...}`.

### Опыт и уровни
- Награда за убийство задаётся полем `xp` в записи моба в `data/mobs.json`.
- В HUD отображаются текущий уровень и прогресс опыта.
- При повышении уровня игра ставится на паузу и открывает полноэкранное меню выбора навыка. Выбор — мышью или клавишами `1`–`9` (Enter выбирает первый вариант).
- Уровень разблокировки навыка задаётся полем `unlock_level` в `data/skills.json`. Сейчас «Рывок» доступен с 1-го уровня, «Импульс» — со 2-го, «Лечение» — с 3-го.


## Настройка дерева навыков (8 ячеек)

Дерево навыков находится во внешнем файле `assets/skill_tree.json` — его можно менять без правки Python-кода. Сетка всегда содержит 8 ячеек (4 столбца × 2 строки). Для каждой ячейки укажите `skill` (ID навыка из `data/skills.json`) и `unlock_level`. Навыки открываются автоматически по уровню персонажа и в порядке ячеек. Чтобы добавить навык, добавьте его определение в `data/skills.json`, положите иконку в `assets/` и укажите относительный путь в поле `icon`. Иконка замка задаётся полем `lock_icon` в `assets/skill_tree.json` (путь относительно `assets/`). Пустые слоты оставлены как шаблоны и показываются закрытыми, пока в них не будет задан ID существующего навыка.


### Настройка меню навыков через assets
Внешний вид экрана повышения уровня настраивается в `assets/skill_menu.json` — код менять не нужно. После изменения закройте и перезапустите игру (или нажмите `F5`, чтобы перечитать данные).

Основные параметры:
- `background_image` — фон меню относительно `assets/`, например `ui/skill_menu_background.png`;
- `slot_unlocked_image` / `slot_locked_image` — текстуры открытой и закрытой карточки;
- `columns`, `rows`, `cell_width`, `cell_height`, `gap_x`, `gap_y`, `grid_y` — сетка и размеры ячеек;
- `icon_size`, `icon_y`, `name_y`, `status_y` — расположение иконки и подписей внутри карточки;
- `title`, `subtitle`, `footer` и `show_*` — надписи и возможность скрыть их;
- `*_color`, `overlay_color`, `overlay_alpha`, `border_width`, `corner_radius` — цвета и оформление.

Все пути к картинкам указываются относительно `assets/`. В комплекте есть примеры текстур `assets/ui/skill_menu_background.png`, `assets/ui/skill_slot_unlocked.png` и `assets/ui/skill_slot_locked.png`. Иконки самих навыков по-прежнему задаются в `data/skills.json`, а порядок и уровни открытия — в `assets/skill_tree.json`. При сборке EXE редактируйте внешние файлы в `dist/assets/` и `dist/data/`.

### Анимация открытия навыков

Все навыки в дереве остаются закрытыми, пока их ID не появится в списке навыков игрока. При повышении уровня открывается только следующий доступный навык по порядку, а замок поверх его иконки плавно исчезает. Настройки находятся в `assets/skill_tree.json`:

- `lock_icon` — иконка замка;
- `unlock_animation_duration` — длительность анимации в миллисекундах;
- `unlock_animation_frames` — необязательный список кадров анимации (пути относительно `assets`); если список пуст, используется плавное исчезновение замка;
- `unlock_flash_image` — необязательная текстура вспышки при открытии.

Для кадров анимации положите изображения в `assets` и перечислите их пути в `unlock_animation_frames` в нужном порядке.

## Визуальный редактор карт

Для создания карты без ручного редактирования JSON запусти из папки проекта:

```bash
python map_editor.py
```

Слева выбери элемент палитры, затем рисуй по сетке левой кнопкой мыши; правая кнопка стирает клетку. Доступны пустота, стены, пять видов платформ, три вида стен, лестниц и шипов, старт игрока, мобы, оружие и выходы. Введи ID и название карты и нажми **«Сохранить в data/maps»**. Редактор создаёт `data/maps/<id>.json` и добавляет ID в `data/maps.json` → `order`. Для обновления карты в работающей игре нажми F5. Редактор использует стандартный Python `tkinter` и не требует дополнительных библиотек.

## Текстуры окружения

Текстуры стен, платформ, лестниц и шипов находятся в `assets/environment/` (в собранной игре — `dist/assets/environment/`). Для каждого типа есть несколько вариантов `wall_1.png`–`wall_3.png`, `platform_1.png`–`platform_5.png`, `ladder_1.png`–`ladder_3.png`, `spikes_1.png`–`spikes_3.png`. Игра выбирает вариант по координатам клетки, поэтому окружение выглядит разнообразнее, но не мерцает и остаётся одинаковым после перезагрузки карты. PNG можно заменять своими текстурами размером 32×32 с прозрачностью.

Чтобы назначить конкретную текстуру отдельной клетке, в легенде карты укажи, например, `"=": {"type": "platform", "sprite": "environment/platform_2.png"}`. Поле `sprite` и настройки `tiles` имеют приоритет над автоматическим выбором.


## Быстрый запуск редактора карт (Windows)

Чтобы открыть редактор без ручного ввода команды, зайдите в папку `2.9` и дважды щёлкните `launch_map_editor.bat`. Скрипт сначала пробует использовать окружение проекта через `uv`, а затем системный Python. Требуется Python 3.10+ с `tkinter`. Подробности также находятся в `РЕДАКТОР_КАРТ.txt`.


### Изменение размера карты в редакторе

В верхней панели `map_editor.py` доступны поля ширины и высоты карты в клетках. Укажи размеры от 5 до 300 по каждой стороне и нажми «Применить». При увеличении новые клетки будут пустыми; при уменьшении края карты обрезаются после подтверждения. Сохрани карту, чтобы записать новый размер в JSON.


## Персонажи (5 героев, выбор перед забегом)

«Новая игра» (в главном меню и в паузе) открывает **экран выбора героя**. Выбор — мышью (клик по карточке, двойной клик или «НАЧАТЬ ЗАБЕГ» — старт),
`←/→` или `1`–`5`, `Enter` — начать, `Esc` — назад. `R` в забеге перезапускает тем же героем; последний выбор запоминается в `data/settings.json` (`last_character`).
`F5` на экране выбора перечитывает все файлы — удобно настраивать оформление.

| id | Герой | Роль | Старт: оружие | Старт: навыки |
|---|---|---|---|---|
| `wanderer` | Странник | Универсал | меч + лук | Рывок |
| `knight` | Рыцарь | Танк | меч + склянка огня | Магический щит (усилен) |
| `ranger` | Инженер | Телекинетик | кинжалы + лук | Телекинез, Волна отталкивания, Телекинетический захват, рывок, двойной прыжок |
| `mage` | Чародей | Маг | меч + посох-искатель | Импульс (усилен) |
| `shadow` | Тень | Убийца | кинжалы + лук | Рывок (быстрый) |

### Характеристики, оружие, навыки, дерево — `data/characters.json`
- `order` — порядок карточек на экране выбора, `default` — герой по умолчанию.
- `name`, `role`, `description` — тексты карточки и панели описания.
- `stats` — правки `data/player.json` только для этого героя. Можно любое поле: `hp`, `speed`, `jump`, `dmg_mult`, `roll_speed`, `roll_time`, `hurt_inv`,
  `hp_regen`, вложенные `"mana": {"max": 160, "regen": 18}` и т.д. Чего нет — берётся из `player.json`.
- `weapons` — стартовое оружие `[ЛКМ, ПКМ]` (id из `weapons.json`).
- `allowed_weapons` — какое оружие герой может подбирать; случайные выпадения тоже только из этого списка. `null` — любое.
- `base_skills` — навыки, доступные с самого начала.
- `skill_tree` — дерево навыков героя: ячейки по порядку, `{"skill": "heal", "unlock_level": 3}` (можно `lock_icon`). Заменяет `assets/skill_tree.json`
  для этого героя (без `skill_tree` используется общий файл). Стартовые навыки стоит ставить в первые ячейки с уровнем 1 — они сразу показаны открытыми.
- `skill_overrides` — правки навыков из `data/skills.json` только для героя (например у Тени `dash` с перезарядкой 1.8).
- `weapon_overrides` — то же для `data/weapons.json` (у Инженера лук дешевле по мане).
- `assets` — папка внешнего вида (по умолчанию `characters/<id>`).

Новые пассивные навыки (`data/skills.json`): `vitality` (тип `max_hp`, `amount`), `fury` (тип `damage`, `multiplier`), `swift` (тип `move_speed`, `multiplier`).

### Внешний вид, анимации, экран навыков — `assets/characters/<id>/`
- `character.json` — скин и анимации героя (поля как у игрока в `player.json`): `skin`, `icon` (иконка в HUD), `color` (цвет героя в меню),
  `anims` (состояние → PNG или папка кадров), `draw` / `draws`, `hand` / `hands`, `anim_fps`, `select` — какая анимация играет на карточке
  (`idle` — обычно, `selected` — у выбранного, `fps`). Пути — относительно `assets/`.
- PNG: `idle.png`, `jump.png`, `roll.png`, `attack.png`, `shoot.png`, `hurt.png`, `ladder.png`, кадры бега в `move/1.png, 2.png …`, кадры стояния в `idle/1.png, 2.png …` (анимация дыхания; её же показывают карточки в меню выбора героя — одиночная игра и лобби), `icon.png`. Анимация прыжка включается, только когда герой реально взлетел или находится в воздухе дольше `AIR_ANIM_DELAY` (0.1 с, `main.py`) — на земле она не мелькает.
  Сейчас это перекрашенные версии исходного спрайта — заменяйте своими картинками с теми же именами.
- `skill_menu.json` — оформление экрана получения навыков этого героя: любые поля из `assets/skill_menu.json`, записанные здесь, перекрывают общие
  (сейчас — свой фон `skill_menu_background.png`, заголовок и его цвет).

### Меню выбора героя — `assets/character_select.json`
Картинки лежат в `assets/ui/character_select/` (`background.png`, `card.png`, `card_selected.png`, `card_hover.png`, `panel.png`, `loadout.png`),
кнопки берут `menu/button.png` / `menu/button_selected.png`. Пустая строка вместо пути — рисуется цветом. Основные поля:
- `background_image`, `overlay_color`, `overlay_alpha` — фон и затемнение;
- `title`, `title_x`, `title_y`, `title_size`, `title_color`, `show_title`;
- карточки: `cards_x` (`null` — по центру), `cards_y`, `card_width`, `card_height`, `card_gap`, `card_positions` (`{"knight": [x, y]}` — поставить карточку вручную),
  `card_image` / `card_selected_image` / `card_hover_image`, `selected_lift`, `selected_border`;
- фигурка героя: `preview_width`, `preview_height`, `preview_y`; подписи: `name_y`, `name_size`, `role_y`, `show_role`, `show_hotkeys`;
- `panel` `[x, y, w, h]` — описание и полоски характеристик; `stats` — какие полоски показывать: `{"label": "Мана", "key": "mana.max", "max": 170}`
  (`key` — путь к полю в характеристиках героя, `percent: true` — показать в %);
- `loadout_panel` — оружие и стартовые навыки; `start_button`, `back_button` `[x, y, w, h]` и их подписи `start_label`, `back_label`; `hint` — подсказка внизу.

Новый герой: запись в `data/characters.json` (+ id в `order`) и папка `assets/characters/<id>/` с `character.json` и картинками (можно скопировать папку существующего героя).

## Босс в конце круга

На последней карте из `data/maps.json` после зачистки обычных противников появляется босс. Если на последней карте обычных мобов нет, босс появляется сразу. В мультиплеере его создаёт хост, а состояние и здоровье передаются всем клиентам обычными сетевыми снимками. Здоровье босса растёт вместе со сложностью круга и числом игроков.

Внешний вид и характеристики босса настраиваются в `assets/boss/boss.json`:

- `name` — имя над полосой здоровья;
- `mob.hp`, `mob.w`, `mob.h`, `mob.draw`, `mob.skin`, `mob.move`, `mob.attacks` — здоровье, размер, спрайт, движение и атаки;
- `health_per_player` — дополнительная доля здоровья за каждого следующего игрока;
- `bar` — положение и размер полосы, цвета, рамка, шрифт и отображение чисел;
- `bar.back_skin`, `bar.fill_skin`, `bar.frame_skin` — необязательные изображения оформления полосы из папки `assets/`.

Замените `assets/boss/boss.png`, чтобы изменить основной спрайт босса. Для анимаций можно добавить в `mob` поле `anims`, например `"anims": {"idle": {"frames": "boss/idle", "fps": 8}, "move": {"frames": "boss/move", "fps": 10}, "attack": {"frames": "boss/attack", "fps": 8}}`, и положить кадры PNG в соответствующие папки внутри `assets/boss/`. После изменения конфигурации нажмите F5 или перезапустите игру.


### Маркеры боссов в редакторе карт

- `B` — точка появления обычного босса.
- `C` — точка появления босса-Моргарта. Поставьте символ `C` в клетку карты и сохраните её.

Оба маркера запускают Моргарта из `assets/boss/boss.json`. Голова появляется в центре клетки маркера, если на карте не закреплён якорь головы (см. ниже).

## Моргарт: голова и руки

Голова — это сам босс. Руки — отдельные части со своим здоровьем, положением и атаками:

- Руки четыре: верхняя/нижняя левая и верхняя/нижняя правая. Каждая живёт на своём месте **относительно головы** (в клетках) и возвращается туда после атаки.
- У каждой руки своё HP (по умолчанию из `boss.json`, в редакторе можно задать на карте). Когда HP заканчивается, рука растворяется и пропадает; её нельзя вернуть.
- Пока жива хотя бы одна рука, голова неуязвима («Щит! Сначала руки»). Когда уничтожена последняя рука, остаётся только голова: она теряет щит и начинает стрелять (атаки с `"requires": "alone"`). **Уровень проходится только убийством головы**; руки на зачистку не влияют.
- Каждая рука приносит опыт (`hands.xp`). Над рукой видна её полоска HP, под полосой босса — общая шкала рук.

### Атаки и паттерны рук

| Атака | Что делает |
|---|---|
| `thrust` | Рука выдвигается по прямой к игроку. На замахе видна линия и точка удара. |
| `slam` | Рука взлетает над игроком и бьёт сверху; ударная волна по кругу (круг виден на замахе). |
| `sweep` | Рука проносится поперёк арены на высоте игрока. Нужно перепрыгнуть полосу или уйти в перекат. |
| `grab` | Рука выдвигается и хватает игрока. Схваченный **оглушён**: не двигается, не атакует, не использует навыки. Рука тащит его к себе и сжимает (урон тиками), затем бросает к центру арены. |
| `clap` | Две руки одного ряда (верхние или нижние) смыкаются у головы на высоте игрока. |

Как вырваться из захвата: быстро нажимать клавиши движения или прыжка (каждое новое нажатие сокращает удержание на `struggle` секунд), либо нанести руке `break_damage` урона (в мультиплеере это могут сделать союзники). Перекат и неуязвимость защищают от захвата. Если рука убита во время захвата, игрок освобождается.

**Паттерн** руки (`hands.patterns`) задаёт порядок атак: `"mode": "cycle"` — по кругу, `"random"` — случайно; `first` — пауза перед первой атакой, `gap` — пауза между атаками. По умолчанию:

- `grabber` — thrust → grab → slam;
- `sweeper` — sweep → thrust → clap;
- `slammer` — slam → grab → slam → clap;
- `hunter` — случайно из thrust / slam / sweep.

Одновременно атакуют не больше `hands.max_active` рук (по умолчанию 2). За каждую потерянную руку паузы сокращаются (`enrage_per_lost_hand`).

### Настройка в `assets/boss/boss.json`

- `mob.hands_gate_head` — `true`: голова неуязвима, пока живы руки (поставьте `false`, если голову нужно бить сразу).
- `mob.attacks` — атаки головы; с `"requires": "alone"` включаются, когда не осталось рук.
- `hands.slots` — спрайт, сторона (`side`), ряд (`row`, пары для `clap`), положение по умолчанию `offset` (клетки от головы), `hp` и `pattern` каждой руки. Можно добавить свой слот (с PNG).
- `hands.patterns` и `hands.attacks` — паттерны и параметры всех атак (`windup`, `active`, `recovery`, `damage`, `knockback`, `reach`, `radius`, `hold`, `tick_damage` и т.д.).
- Новая атака руки: класс-наследник `HandAttack` с декоратором `@hand_attack("имя")` в `boss_hands.py`, параметры в `boss.json`.

## Руки Моргарта в редакторе карт

В редакторе (`launch_map_editor.bat`) есть панель «Моргарт: голова и руки»:

Панель появляется, только когда на карте стоит маркер `C` (Моргарт), и пропадает вместе с ним. На картах без маркера и с другими боссами в редакторе нет ничего про Моргарта. Для будущих боссов будут свои маркеры и панели.

1. Включите «Режим Моргарта». Пока он включён, ЛКМ двигает метки, а клетки не рисуются.
2. Выберите часть (голова или любая из четырёх рук) и щёлкните или перетащите по карте. Ближайшая к курсору метка выбирается автоматически.
3. Положение руки хранится относительно головы: если сдвинуть голову, руки поедут вместе с ней.
4. В строке каждой руки: галочка «Есть» (руку можно убрать с карты), HP и паттерн.
5. «Сохранить в data/maps» записывает `morgart_layout` в файл карты. Если игра уже запущена, нажмите F5.

Формат в файле карты (смещения в клетках от центра головы, якорь головы — доли размера карты 0..1):

```json
"morgart_layout": {
  "anchors": { "head": [0.5, 0.3] },
  "hands": {
    "upper_left":  { "enabled": true,  "offset": [-11, -1.5], "hp": 260, "pattern": "grabber" },
    "lower_right": { "enabled": false, "offset": [11, 2] }
  }
}
```

Карты, сохранённые старой версией редактора (`left_hand`/`right_hand`), читаются как раньше и конвертируются при открытии в редакторе. Физическое ядро Моргарта стоит в центре головы и не двигается (гравитация, отбрасывание и перемещение отключены).
